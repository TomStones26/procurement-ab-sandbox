# 采购流程 A/B 实验沙盒 · PR 审批分级授权

> 把「低值低风险采购申请的串行人工审批」换成「规则引擎自动放行 + 事后审计」，
> 并用规范的 A/B 方法论把这个改动验证清楚。
>
> **数据来自两份公开真实采购数据源**（USASpending.gov + World Bank），
> 点击下方链接可直接在线运行沙盒。

**在线沙盒** → <https://tomstones26.github.io/procurement-ab-sandbox/>

## 一、结论先行

沙盒默认结果（种子 20260、日均 380 条 PR、28 天、自动放行阈值 ¥50,000）：

| 指标 | 对照组 A（两级串行人工审批） | 实验组 B（规则引擎自动放行） | 变化 |
|---|---|---|---|
| **PR→PO 周期**（几何均值） | 47.1 h | 33.1 h | **−29.6%**（95%CI [−31.9%, −27.4%]） |
| 48h 完成率 | 53.9% | 64.6% | +10.6 pp |
| 事后审计异常率（护栏） | 1.11% | 1.89% | +0.78 pp（非劣界 1.0 pp，**未越界但需监控**） |
| 采购价格偏差（护栏） | +0.27% | +1.42% | +1.15 pp（非劣界 1.5 pp，**未越界但需监控**） |

**落地建议：有条件放量上线** —— 限金额阈值、限低风险品类、全量留痕、设熔断条件。

### 三条最值得记住的发现

**1. 效果确实存在，而且很大。** 周期从 47.1 小时降到 33.1 小时，降幅 29.6%。这不是"审批快了一点"，而是**有三分之一的采购申请当天就能走完流程**。

**2. 护栏指标根本测不动 —— 这是本项目最反直觉的一条。**
主指标只要 **45 条**样本就有 80% 把握检出效应，而"审计异常率从 1.20% 涨到 1.50%"这种量级的护栏变化，每组需要 **23,228 条**。**相差 516 倍。**
按沙盒的 380 条/天算：主指标 **1 天**就能测，护栏要跑 **122 天**。
→ 所以护栏不能用"统计显著"当判据，只能用**方向 + 非劣界 + 持续监控 + 熔断**。

**3. 抽检比例救不了你。** 把事后抽检从 10% 拉到 40%，护栏点估计几乎不动。
因为**抽检覆盖率就是异常发现率的上限**——抽 10% 最多只能看见 10% 的问题，真实异常率必然被系统性低估。

## 二、聚焦点：只动一个节点

不做供应链全景看板。整条链路只干预**一个**环节：

```
需求提出 → 创建 PR → 【PR 审批 ✦ 本实验唯一干预点】 → 询价/定点 → PO 签发 → 收货 → 三单匹配 → 付款
```

| 组别 | 策略 |
|---|---|
| **对照组 A** | 所有 PR 走「直属主管 → 采购经理」两级串行人工审批 |
| **实验组 B** | `金额 ≤ 阈值` 且 `品类风险 = 低` 的 PR，由规则引擎做「预算科目余额 / 合格供应商名录 / 重复采购」三项校验后自动放行；其余 PR 维持原流程。另加事后抽检 |

**为什么选这个点**：它同时满足四个条件——① 高频（占 PR 总量约六成）；② 单笔风险低（有金额阈值兜底）；③ 人工在此环节几乎不创造增量判断（三项校验都能规则化）；④ 效果可量化且可直接换算成人力工时。

### 值得动手试的旋钮

| 操作 | 会看到什么 |
|---|---|
| 自动放行阈值 ¥5 万 → ¥100 万 | 主指标继续变好（周期比 0.70→0.62），但**护栏先崩** —— 价格偏差越过 1.5pp 非劣界，结论从「有条件放量」变成「先补管控」 |
| 事后抽检比例 10% → 40% | 护栏点估计几乎不动 —— 覆盖率就是发现率上限，抽检兜不住 |

| 实验天数降到 7 天 | 主指标仍显著，但护栏指标完全测不出来 |
| 点「运行 A/A 验证」 | 假阳性率实测：单次检验 5.3% ／ 每天偷看不校正 **27.7%** ／ OBF 序贯边界 5.0% |

## 四、数据从哪来

两份通过**官方 API 实时抓取**的公开真实数据，抓取脚本与原始数据快照在 `pipeline/`。

| 数据源 | 用途 | 许可 |
|---|---|---|
| **USASpending.gov** `/api/v2/search/` | 美国联邦采购合同授予数据：43 个对数金额分带的**真实计数** + 供应商 / PSC / NAICS 聚合 | 公有领域 |
| **World Bank Procurement Notices** | 世行采购公告 1,000 条，用于采购方式构成 | CC BY 3.0 IGO |

**采集规模**：43 个对数金额分带 × 2 个财年（FY2023 / FY2025），逐带调用计数接口，得到 **3,818,521 条**真实合同的金额分布（覆盖 $1,000 – $37M，占该期间全部合同动作的 35.5%）；聚合端点另取 500 家供应商、40 个 PSC 品类、40 个 NAICS 行业。

### 真实数据用在哪、没用在哪 —— 这一节必须看

**用了**：金额分布的**形状**（直接抽经验分布）、品类与供应商构成、采购方式构成。

**没用**：公开数据里**没有 PR 级审批时间戳**。流程耗时部分由结构化仿真生成（带重尾、周末低谷、积压放大、按风险等级分化等真实特征），**不是实测**。

量级不可直接套用，因此只做了一次**显式可追溯的尺度平移**（×3.2006：真实中位数 $5,624 → 沙盒中位数 ¥18,000），并在真实分布 P99 处截断。

### 一个实测结论：这笔钱的分布不是对数正态

| 拟合方式 | 预测 P99 | 实测 P99 | 偏差 |
|---|---|---|---|
| 四分位距反推 σ | $384,268 | $2,998,077 | **低估 7.8 倍** |
| 对数空间最小二乘 | 虚高约 4,898 倍 | — | **高估 4,898 倍** |

两个方向都失败。小额区间同样明显：$1,000–$1,500 这一带，对数正态只预测出实测计数的 **38%**。

→ 所以沙盒**不引入任何参数化假设**，金额直接从这个经验分布抽样。第 2 页有分带偏差诊断图可以直接看。

## 五、方法论要点（可直接当团队 SOP）

**事前**
- 主指标唯一且冻结口径：PR→PO 周期，用**对数尺度几何均值比**（重尾数据用算术均值会被尾部带跑）
- 护栏指标设**非劣界**而非显著性判据：审计异常 < 1.0pp、价格偏差 < 1.5pp
- MDE 与样本量开跑前算好：要检出 12% 的周期改善，每组需 346 条、合计 692 条（约 1.8 天）
- **A/A 验证过分析管线**：单次检验假阳性率 5.3%，接近 5% 才算可信
- 停止规则事前确定，不允许事后改

**事中**
- SRM 每日监控，两级判定：`p<0.001` 或偏离 >2% → 硬失败；`p<0.01` → 告警
- 序贯检验用 **Lan-DeMets O'Brien-Fleming 消耗函数 + Armitage–McPherson 精确积分**求临界值，**不是** `1.96·√(K/k)` 近似。实测整体第一类错误率 5.0%（K=28）、4.0%（K=56）

**事后**
- 同一效应用四种方法算，口径一致才下结论（对数 t / 原始 t / Bootstrap 中位数 / CUPED）
- **CUPED 压方差**：用「同品类同金额档的历史平均审批时长」作协变量，实测 ρ=0.570、方差缩减 **34.5%**，等效于凭空多出 53% 的样本
- **ITT 与 CACE 都报**：覆盖率仅 33%，ITT 显示周期降 30%，被覆盖人群实际降 66% —— **差一倍以上，不能只报一个**
- **异质性（CATE）**：效应集中在低风险品类（0.457×）与覆盖人群（0.332×），高风险品类无变化
- **BH 校正**：次指标与护栏一起检验了 6 项，不做校正等于偷偷放水

## 七、已知局限（诚实清单）

1. **流程耗时是仿真，不是实测。** 公开数据没有 PR 级审批时间戳。落地前必须用企业内部 OA / 采购系统日志重新标定。
2. **无长期效应评估。** 4 周实验看不出「申请人是否会把大额采购拆成小额来钻阈值空子」。
3. **ITT 低估价值，CACE 高估可推广性。** 阈值上调后边际人群风险画像更差，效应与护栏都不能线性外推。
4. **轻度溢出污染。** 同一采购员同时处理两套流程，可能把新流程习惯带入对照组。
5. **护栏测量误差。** 10% 抽检最多只能发现 10% 的异常，真实异常率必然被低估。把抽检拉到 40% 也几乎不改变点估计。

## 八、复现方式

沙盒侧：打开页面即可，所有统计口径由随机种子完整复现（换种子结论不变）。

数据侧（需 Python 3 环境）：

```bash
python pipeline/01_fetch_amount_bands.py           # 约 14 分钟
python pipeline/02_fetch_category_aggregates.py    # 约 1 分钟
python pipeline/03_build_baseline.py               # 生成 data.js
```

验证脚本（需 Node）：

```bash
node pipeline/tests/test_e2e.js      # 端到端：基线注入 → 仿真 → 全部分析口径
node pipeline/tests/test_seq.js      # 序贯边界：OBF 参考表对照 + 第一类错误率蒙特卡洛
node pipeline/tests/test_seed.js     # 种子稳健性：14 个种子的基线与效应波动
node pipeline/tests/test_audit.js    # 审计异常护栏的抽样分布核查
node pipeline/tests/test_engine.js   # 引擎冒烟测试 + 分布函数自检
```
